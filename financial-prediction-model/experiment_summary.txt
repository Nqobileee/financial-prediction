BEST TRIAL: V1.2a (Label Encoding - same as V1.1d)
- No improvement over V1.1d baseline
- Ordinal mapping HURT performance significantly (F1 dropped 0.20)
- Frequency encoding adds features but no meaningful improvement

KEY FINDINGS:
1. Tree models (LightGBM) don't benefit from manual ordinal encoding
2. Label encoding is already optimal for this data
3. Frequency encoding adds 31 features but marginal benefit
4. V1.2b failure suggests some column values weren't mapped correctly

CONCLUSION:
- V1.1d remains the best V1.x approach
- Move to V1.3 (Attitude/Perception cleaning) for potential gains

VERSION 4.0 - BACK TO BASICS (ANTI-OVERFITTING)
================================================================================
Date: February 10, 2026
File: models/financial_prediction_v4.py

DIAGNOSIS:
- V2 and V3 both showed HIGHER local CV but LOWER leaderboard scores
- This is classic overfitting - model memorized training patterns
- Feature engineering created patterns that don't exist in test data

STRATEGY:
- Use ONLY original 37 features (NO engineering)
- Strong regularization to prevent memorization
- Simpler tree structure
- 5-seed ensemble for stability

PARAMETERS (HIGHLY REGULARIZED):
- n_estimators: 400
- learning_rate: 0.05
- num_leaves: 20 (REDUCED)
- max_depth: 5 (REDUCED)
- min_child_samples: 50 (INCREASED)
- subsample: 0.7
- colsample_bytree: 0.7
- reg_alpha: 1.0 (STRONG)
- reg_lambda: 1.0 (STRONG)
- min_split_gain: 0.01

RESULTS:
- Accuracy: 0.8744 (lower than V1-V3)
- F1 Macro: 0.7992 (lower than V1-V3)
- Log Loss: 0.3168 (lower than V1-V3)
- Features: 37

================================================================================
KEY INSIGHTS
================================================================================

1. MOST PREDICTIVE FEATURES:
   - Financial ratios (income/expenses, income/turnover)
   - Owner demographics (age, age at business start)
   - Business experience (years, months, experience ratio)
   - Financial access (banking score, insurance)

2. CLASS IMBALANCE CHALLENGE:
   - High class (4.9% of data) consistently has lowest recall (~60%)
   - Consider class weights or oversampling in future versions

3. CRITICAL: OVERFITTING PATTERN DETECTED:
   - V1 → V2 → V3: Local CV improved each time
   - But leaderboard score DROPPED each time
   - This means: higher local CV = worse real-world performance
   - LESSON: Simpler models generalize better

4. ANTI-OVERFITTING STRATEGIES (V4):
   - Fewer features (original only, no engineering)
   - Strong regularization (reg_alpha=1.0, reg_lambda=1.0)
   - Simpler trees (num_leaves=20, max_depth=5)
   - More samples required per leaf (min_child_samples=50)

================================================================================
RECOMMENDATIONS FOR NEXT VERSIONS
================================================================================

IF V4 STILL OVERFITS, TRY:
1. Even stronger regularization
2. Remove some original features (use only top 20-25)
3. Increase min_child_samples to 100+
4. Use only 2-3 folds instead of 5
5. Try Ridge/Logistic with heavy regularization

IF V4 WORKS (LEADERBOARD IMPROVES):
1. Gradually add back the best engineered features one at a time
2. Target encoding for country (out-of-fold)
3. CatBoost with default regularization (naturally more regularized)

V5+ IDEAS:
1. Simple ensemble: V1 + V4 average
2. Blending multiple simple models
3. Country-specific simple models
